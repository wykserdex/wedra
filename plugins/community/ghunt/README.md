# ghunt

OSINT по Google-аккаунтам через GHunt (mxrch/GHunt): имя, Gaia ID, аватар, даты
редактирования профиля, связанные сервисы.

Установка внешнего инструмента: `pipx install ghunt` (или `pip install ghunt`).
Путь к бинарю переопределяется env `GHUNT_BIN`.

Авторизация обязательна: сначала `ghunt login` (нужен браузер и расширение
GHunt Companion). Сессия хранится не в env, а в файле `~/.malfrats/ghunt/creds.m`
(base64+JSON) — GHunt 2.3.4 не читает ни одной переменной окружения.
Плагин переменную `GHUNT_TOKEN` только пробрасывает в дочерний процесс и не
требует её наличия, в манифесте она объявлена как секрет; сам инструмент её
игнорирует. Так как файл сессии лежит вне рабочего каталога плагина, в манифесте
`filesystem: readwrite`.

Про `mode`:

- `email` — рабочий сценарий: `ghunt email <адрес> --json <файл>`.
- `username` — **такой подкоманды в GHunt 2.x нет**. По исходнику `ghunt/cli.py`
  и по `ghunt --help` есть `login`, `email`, `gaia`, `drive`, `geolocate`,
  `spiderdal` ( `--json` есть у всех, кроме `login`).
  Плагин ничего не подменяет и не выдумывает: `mode` уходит в командную строку как
  есть, поэтому на реальном GHunt `mode: username` завершится ошибкой `tool_failed`.

Форма JSON-выгрузки апстримом не зафиксирована, разбор намеренно плоский и
консервативный: `records` — список `{field, value}`.
