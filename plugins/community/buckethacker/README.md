# buckethacker

Поиск открытых облачных хранилищ (S3/Azure Blob/GCS/Spaces) по имени бакета или
storage-аккаунта. Обёртка над CLI `buckethacker`, отчёт читается из stdout.

Установка внешнего инструмента: `pip install buckethacker`.
Путь к бинарю переопределяется env `BUCKETHACKER_BIN`.

ДОНОРА НЕ СУЩЕСТВУЕТ. Проверено: пакет `buckethacker` на PyPI отсутствует
(`pip download` → No matching distribution; `pypi.org/pypi/buckethacker/json` →
404), репозиторий `ingo60/buckethacker` на GitHub не существует (404), поиск
репозиториев по имени `buckethacker` даёт 0 результатов, а у пользователя
`ingo60` вообще нет репозиториев про облачные хранилища (13 репо, все — язык
Frege). Упоминание донора в registry.yaml не подтверждается ничем.

CLI собран консервативно — только позиционный аргумент `<name>`, без флагов;
отчёт читается как JSON, а при его отсутствии разбирается текст (эвристика по
маркерам). Ключи не нужны: поиск анонимный.

Реальная замена при том же назначении (поиск открытых хранилищ по имени):
`initstring/cloud_enum` (2144 звезды) — ровно та же задача, ставится только из
git, `pip install git+https://github.com/initstring/cloud_enum`, входной бинарь
`cloud_enum`, ключевой флаг `-k/--keyword` (НЕ позиционный аргумент), отчёт через
`-l <logfile> -f json`. В этом же репозитории уже есть плагин `cloud_enum` с этим
донором, поэтому подменять им buckethacker — значит плодить дубль; замена
требует правки registry.yaml.
