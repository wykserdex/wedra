# Свой плагин за 15 минут (для авторов, без подглядывания в чужой код)

Выверено на 8 реальных граблях внешних тестеров (M5_FEEDBACK.md).
Путь: скелет → своя логика → контракт-тесты → своя цепочка. SDK не существует —
плагин это обычный скрипт.

## 0. Бинарник (1 мин)

Release-архив → `bin/<ваша ОС>/tool` → `chmod +x`. Проверка: `./tool --help`.
Все команды ниже — `tool` (один бинарник) или `tool.exe` под Windows.

## 1. Скелет (2 мин)

```bash
tool plugin create plugins/мой_плагин --author ТЫ --description "Что делает" --example array
#   --author/--description: чтобы не было TODO в манифесте
#   --example string (по умолчанию) | array — форма входа
```

Гарантия генератора: скелет сразу валиден и зелёный:

```bash
tool plugin validate plugins/мой_плагин   # OK
tool plugin test plugins/мой_плагин       # все тесты passed
```

## 2. Контракт за 90 секунд (это весь «SDK»)

- **stdin** ← JSON со входом (ядро собирает его из секции `input` манифеста).
- **stdout** → РОВНО один JSON: `{"status":"ok","output":{...}}` (exit 0, успех)
  или `{"status":"error","error":{"code","message","retryable"}}` (exit 1 — доменная
  ошибка: плагин отработал, но результат отрицательный). Любой мусор на stdout /
  падение ≥2 — платформенная ошибка, стопит ран.
- **stderr** — любые логи, попадут в журнал рана (`runs/<id>/journal.jsonl`).
- Судьбу цепочки решает YAML пайплайна (`on_error: stop|skip|retry`), не плагин.
- Шпаргалка типов лежит прямо в шапке сгенерированного `plugin.yaml`:
  `type: string|number|boolean|array|object`, `format` (только для строк):
  `text|email|url|ip|file_ref`.

## 3. Своя логика

Правим `main.py` (в шаблоне уже есть `fail()`/`ok()` и чтение stdin).
Правила выживания, заученные тестерами:

1. **Не гадай тип** — guard'ь: вход `type: array`? `isinstance(items, list)` с
   платформенной ошибкой. Статика validate проверяет ПАЙПЛАЙН, в рантайме
   тип твоего входа плагину не гарантирован — контракт проверяй сам.
2. **Относительные пути — от папки плагина**: cwd процесса = директория плагина,
   не корень проекта (ядро с v0.2 предупредит ⚠, если такой путь есть от корня).
3. **Доменная ошибка vs платформенная**: «пользователь дал пустой текст» → exit 1;
   «мне прислали битый JSON» → exit 2. Тестеры ошибались ровно здесь.

## 4. Контракт-тесты — твой цикл разработки

```bash
tool plugin test plugins/мой_плагин   # гоняет тот же subprocess-протокол, что и ядро
```

В `plugin.test.yaml`: кейсы `input → expect`. Матчеры: литерал (глубокое равенство),
`{ equals: X }`, `{ contains: "..." }` (строка И массив), `{ present: true }`,
`{ type: "array" }`; `env: {...}` — секреты/mock на время теста; `input_raw` — сырой
stdin для тестов битого JSON. Прогон включает enforce: вернул поле не того типа —
тест красный даже если Python «всё напечатал».

## 5. В цепочку (пайплайн, v0.2)

```yaml
format_version: "0.2"
pipeline:
  name: my_first
  input: { text: "привет мир" }
  steps:
    - id: mine
      plugin: plugins/мой_плагин
      # from в манифесте — только дефолт; здесь можно перекрыть:
      # bind: { text: input.text }
      on_error: stop
```

```bash
tool validate pipelines/my_first.yaml   # ловит типы/форматы/разводку ДО запуска
tool run pipelines/my_first.yaml        # --yes = авто-accept гейтов (CI)
```

Один плагин дважды в цепочке — нормально: второй вызов с другим `bind:`
(см. `pipelines/llm_same_provider.yaml`, `dir_snapshots.yaml`).

## 6. Грабли, на которые уже наступили (и как их не наступить)

| Грабля | Рецепт |
|---|---|
| `format: json` на `type: array` → взрыв в пайплайне | format — только строкам; массиву хватит `type: array` |
| относительный путь в pipeline → not_found | пути — от папки плагина или абсолютные; смотри ⚠ от run |
| опечатка в `bind:` порту | `validate` перечислит существующие порты |
| «объявил string, вернул int» | enforce скажет это в plugin test сразу |
| плагин читает выход skip-able шага | вход сделай `optional: true`, иначе validate красный |

## 7. Прислать плагин

Папку плагина (manifest + код + plugin.test.yaml) — автору/в issues репы.
Зелёные контракт-тесты = гейт принятия (так в репо уже лежат text_analyzer и
dir_lister — внешних авторов, с атрибуцией в манифесте). Если плагин учит новому
сценарию — из него соберём демо-пайплайн.
